# WindowsWallPaper

一个 Windows 桌面壁纸播放器：**每块显示器各自播放自己的图片列表**。

| 能力 | 说明 |
| --- | --- |
| 多屏独立 | 每屏选自己的播放列表，因此有各自的内容、顺序、间隔与填充方式 |
| 每屏独立换纸 | 各按自己的间隔切换，**谁也不等谁**；一块慢一点、或者被单独暂停，都不影响另一块 |
| 只有随机播放 | 顺序/倒序已取消。随机只记**最近 10 张的名字**，因此"刚看过的那几张"不会马上又来；点「重新加载」就是新的一轮随机。**列表在「列表」页的先后顺序只决定界面上怎么排（以及播放页下拉菜单的顺序），不决定播放次序** |
| 列表排序 | 「列表」页每行左边有个手柄，**按住上下拖**就能调顺序；播放页选列表的下拉菜单按同一顺序排 |
| 删除不想要的壁纸 | 播放页每块屏卡片右上角有「删除当前壁纸」：它把当前这张图**移进软件回收站**（`data\trash\`，不彻底删除）并立刻换下一张——换上的就是页面上预告的那张「下一张」 |
| 回收站页（相册） | 左侧「回收站」页以相册形式列出被删掉的图，每张下面有**恢复**（绿底，放回它原来的位置）与**删除**（红底，送进系统回收站），顶部还有**全部删除**。缩略图按比例缩进格子里，**整张图都看得见**（不裁切），便于判断要不要留；回收站相关的东西**只在这一页**（设置页不再重复一份）。删除时记下的原位置就在条目里的 `origin.json`，因此恢复不需要你记得它原来在哪 |
| 固定单图 | 某块屏可以只显示一张指定的图（不轮播），缓存只留一份，换了图就更新它 |
| 每屏独立筛选 | 按长宽比、最小尺寸挑选图片。主屏留横图、副屏留竖图是典型用法 |
| 目录树级选择 | 在界面上勾选图库里的哪些子目录参与轮播，不必挪动文件 |
| 大图库 | 几万张图也能用：JSONL 索引 + 按需加载，扫描时只读图片头部 |
| 一键重扫全部 | 「图库」页最上面一个按钮把**所有**图库都重扫一遍：**已有的索引不动**，只打开新增或有改动的文件，删掉的图从索引里移除。结果列出每个图库的"新增 / 更新 / 删除 / 未变" |
| 便携 | 数据放在程序目录旁边，整个文件夹拷到哪都能跑 |
| 托盘常驻 | 默认启动时不显示主界面；**单击**托盘图标做什么可以配（打开主界面 / 换一张壁纸），右键是菜单（「轮播中」「NSFW」两项**带勾显示当前状态**） |
| 只跑一个实例 | 重复启动**不会再开第二个进程**：托盘图标、壁纸、设置都只有一份，第二次启动只是把已经在跑的那个主界面打开 |
| NSFW 模式 | 播放页顶部一个按钮（或全局快捷键）把每块屏切成它自己那张固定图并停下轮播；按钮绿 = 未开启、红 = 已开启；下次启动仍保持这两张 |
| 全局快捷键 | NSFW 模式、暂停/继续、下一张、上一张、显示主界面各一个，默认 `Ctrl+Alt+S` / `P` / `→` / `←` / `W`，在「设置」页改 |
| 每屏暂停 | 可以只让某一块屏停止换纸，另一块照常 |
| 显示器改名 | 在「播放」页双击显示器名（`\\.\DISPLAY1`）就地改成一个好认的英文/数字名字；只影响显示 |
| 每屏壁纸预览 | 「播放」页每块屏的卡片上并排两格：**当前显示**与**下一张**，都带缩略图与路径；「下一张」还写着还有多少秒切换。显示的那张就是随后真会换上的那张 |
| 记住窗口大小 | 你把界面拉成多大，下次启动就还是多大（存在 `data\window-state.json`，只记大小、不记位置） |
| 中文界面 | 全中文，没有语言切换 |
| 从不动你的文件 | 只读图片；目录选择与排除都记在自己的配置里 |
| 不还原壁纸 | 关闭、退出、停止轮播都不把你的壁纸改回去 |

> ## 只有图片，没有视频
>
> 视频壁纸所需的"铺满屏幕的宿主窗口"这条路径已经从程序里**删掉**了：
> 它要建窗口、要有 D3D 设备，而图片壁纸由系统渲染根本不需要它——
> 一旦建出来它会盖住系统壁纸，用户看到的就是一片灰色。
>
> 现在程序里没有任何视频相关的接线、命令与界面元素。
> 引擎（`wwp-core`）里当年验证过的窗口、合成、解码、音画同步代码还留在仓库里
> 供以后查考，但它们已经不被任何地方调用，因此**运行时不产生任何开销**。

## 快速开始

拿到 `release\WindowsWallPaper\` 这个文件夹之后：

1. **双击 `WindowsWallPaper.exe`**。程序会自动在当前文件夹里建出 `config/`、`data/`、`logs/`、
   `webview2/`，不需要安装、不需要管理员权限。
   - 默认**不弹出主界面**，只在托盘里待着（壁纸软件不需要每次开机都看到设置窗口）。
     想改这个行为：托盘图标 → 打开界面 → 「播放」页 → 「启动与窗口」里取消勾选"启动时不显示主界面"。
   - 你把界面拉成多大，**下次启动就还是多大**（只记大小、不记位置；换到更小的显示器上会自动收进屏幕里）。
2. **进「图库」页 → 点「新增图库」**，选一个放图片的文件夹。可以加多个，
   清单**按路径排序**显示（图库的增删**只在这里**做）。
3. **在那块图库上点「扫描」**（或者用页面上方的**「全部重新扫描」**一次把所有图库都扫一遍）。
   右上角会出现一条浮窗显示进度；扫描结束后它会显示"扫描完成（新增 X、更新 Y、删除 Z）"，
   停留几秒；页面上会留一张结果卡，逐个图库写明变了什么。
   - 只读图片头部拿尺寸，**不加载整张图**；
   - 未变化的文件在重扫时会被复用，**不重新打开**；
   - 磁盘上删掉的图会从索引里移除、新加的会被加上，**已有的条目不动**——
     所以"重新扫描"只是把索引对齐到磁盘现状，不会让播放列表丢东西。
4. **想只播其中一部分？点「选择目录…」**。目录树就在**这一行的下方**展开（只列目录，不列文件），
   按需要勾选。取消勾选一个目录时，它的**全部子目录一并取消**。
   树上有「全选」「全不选」两个按钮。
5. **切到「列表」页 → 「新建列表」**，在它下面勾选这个列表要用哪几个图库。
   一个列表可以关联多个图库；一个图库也可以被多个列表共用；勾选清单与「图库」页**顺序完全一致**。
   刚加进图库清单、还没被任何列表勾选的图库会标成「未被使用」——它不会被播到。
   列表多了以后，**按住每行最左边的手柄上下拖动**就能调顺序（播放页的下拉菜单按同一顺序排）。
6. **回「播放」页，给每块屏选播放列表**，然后点「开始轮播」。
   **没有选播放列表的屏不会换纸**——这就是"某块屏不轮播"的做法。
7. **关掉窗口**只是隐藏到托盘（默认行为）。托盘菜单（右键，或左键点图标打开界面）五项依次是：
   **显示主界面 / 切换到下一张 / 轮播中 / NSFW / 退出**。后两项前面带勾，**勾 = 此刻正是那个状态**：
   「轮播中」勾着就是正在轮播，取消勾选的状态就是已暂停或没在跑（点一下即可开始/继续/暂停，
   与界面上的「暂停/继续」按钮同一件事）；「NSFW」勾着就是正在 NSFW 模式里。
8. **重复双击 exe 不会再开一个程序**：第二次启动只会把**已经在跑的那个**主界面打开
   （哪怕它是隐藏到托盘的状态）。同一个会话里永远只有一个进程——否则两个进程会
   各自换壁纸、各自重写设置，还会在托盘里留下两个一模一样的图标。
   `--diagnose` / `--scan` 这类命令行工具不受此限制（排查时正需要程序跑着也能用）。

> **本程序永远不会还原你的壁纸。** 关闭窗口、退出、停止轮播、崩溃后重启都不还原：
> 桌面上留着的就是它最后换上的那张。

设置改了之后**保存就生效**（后端会比对该不该重建，只有真的变了才重建）。要手动强制刷一次，
就点播放页的「重新加载」：它会停止当前轮播、按当前设置重建，**并且不动你屏幕上现在那张图**，
到下一个间隔才换。想立刻换一张就用「下一张」。

> 「重新加载」不立刻换纸是刻意的：原先它走的是"重建并立刻换一张"，
> 用户看到的现象就是"点一下它很快地切了一次"。他明确要的是"直接重新加载"。

想要更细的控制，看「播放」页的每屏区块：图像比例筛选（原「长宽比区间」）与最小尺寸可以逐屏设，
「固定单图」可以让这块屏只显示一张指定的图；
间隔与填充方式属于**播放列表**，在「列表」页改（列表的先后顺序也在那里拖动调整）。

## 删掉不想要的壁纸（回收站页）

轮播时看到一张不想要的图，不用去资源管理器里找它：

**「播放」页 → 那块屏卡片的右上角 → 「删除当前壁纸」**。点一下它会：

1. 把当前显示的那张图**移动**到 `data\trash\`（**软件回收站**）——
   **不是彻底删除，也不是直接丢进系统回收站**；
   同时把它**原来的完整路径**记在条目里的 `origin.json`；
2. 把它从图库索引里去掉（否则下一次「重新加载」它又会回到候选里）；
3. 立刻给这块屏换下一张。

之后到左侧的**「回收站」页**（相册形式）里处理：每张图下面两个按钮——

- **恢复**（绿底）：把它**放回原来的位置**。原来的目录不在了就建出来；
  原位置已经有一个同名文件时**绝不覆盖**，而是另存成 `名字 (恢复).jpg`。
  恢复之后程序会**自动把这个图库的索引补上**（一次增量扫描，只读这一张），
  因此它马上就重新参与轮播；
- **删除**（红底）：把这一项送进**系统回收站**（仍然可以从桌面的回收站还原）。

顶部还有一个**「全部删除」**，以及「打开文件夹」「刷新」。

> **"恢复"靠的是删除那一刻记下来的原位置**，不是靠你去回忆。
> 每个条目是 `data\trash\<删除时间>-<原文件名>\` 这样一个目录，
> 里面有 `origin.json`（原位置、原名、删除时间、大小）和图片本体。
> 一个条目一个目录，顺带解决了旧版"不同目录下同名文件要靠 `01 (2).jpg` 区分"的麻烦。

**「设置」页 → 回收站**里只保留「打开回收站文件夹」与当前项数/占用——
逐张恢复与删除都在「回收站」页做（同一件事不留两个入口）。

> 为什么分两级、而且每一步都可恢复：用户明确要求"不要放到系统回收站，
> 也不要彻底删除，而是放到软件的数据文件夹里面"，同时"全部删除时把所有东西
> 都放到系统回收站"。这两条一起意味着：这个功能里的任何一步都不会让一张图
> **不可恢复地**消失——想彻底删掉，得你自己在系统回收站里再清一次。

> 旧版本（1.3.0）删掉的条目是平铺在 `data\trash\` 下的文件，那时候还没有记录
> 原位置。它们照样会列在相册页里，只是「恢复」是灰的（会说明原因），
> 「删除」照常可用。

## NSFW 模式与全局快捷键

需求场景：正在看视频、打游戏、或者把屏幕给别人看的时候，不想让壁纸每隔两分钟就换一次，
而是想固定显示两张自己挑好的图。

用法：

1. 在「播放」页每块屏的卡片里，给「NSFW 壁纸」各选一张图（点「选择图片…」）。
   这两张图会**提前按屏裁好并缓存**，因此真正切换时几乎是瞬间完成的。
   填充方式固定为 `Fill`（裁切填满）。
2. 点播放页顶部那一行的 **NSFW** 按钮（未开启时是绿色），或者按全局快捷键（默认 `Ctrl+Alt+S`）。
   程序会立刻把每块屏切成它自己的那张图，并**停下轮播**；NSFW 按钮同时变成红色，
   表示"已经在 NSFW 模式里了"。
3. 再点一次 / 再按一次 → 退出 NSFW 模式，**回到进入之前那张壁纸**（不重新抽签），
   并恢复按播放列表轮播。

> 第 3 条是 1.13.0 改的。在那之前退出 NSFW 走的是"每块屏各换一张新的"，
> 用户看到的现象就是"一退出壁纸就被换掉了"。现在进入 NSFW 时先把屏幕上那两张
> （含预告的下一张）记在内存里，退出时原样放回去、第一次自动切换用原来预告的那张，
> 倒计时按配置的间隔重新起算。

**无论是否处于 NSFW 模式，都可以改这两张图。** 在 NSFW 模式里改的话，新的那张会**立刻切上去**
（不会出现"改了设置但屏幕上还是旧图"）；不在 NSFW 模式时只是把新图解好缓存，点 NSFW 时才用。

细节：

- **下次启动仍然是这两张**：程序把"当前处于 NSFW 模式"记在 `data\nsfw-state.json` 里，
  启动时优先读它，不会自动开始轮播。
- 进入 NSFW 模式**不会还原你原来的壁纸**（本来就没有"原来"这个概念，见上文）。
- 这个模式原先叫 SAFE，1.13.0 起全面改名为 NSFW：界面、托盘、快捷键、
  配置字段（`safe_hotkey` → `nsfw_hotkey`、`safe_wallpaper` → `nsfw_wallpaper`）
  与状态文件都换了名字。**旧配置与旧状态文件照常读得进来**，
  下一次保存才写成新名字——所以升级不会丢你自己的设置。

### 五个全局快捷键

| 快捷键 | 默认写法 | 作用 |
| --- | --- | --- |
| NSFW 模式 | `Ctrl+Alt+S` | 进入 / 退出 NSFW 模式 |
| 暂停 / 继续 | `Ctrl+Alt+P` | 按一下暂停**所有**屏，再按一下继续 |
| 下一张 | `Ctrl+Alt+Right` | 所有屏各换一张 |
| 上一张 | `Ctrl+Alt+Left` | 所有屏各退回上一张 |
| 显示主界面 | `Ctrl+Alt+W` | 把设置窗口显示出来（等价于点托盘的「打开主界面」） |

写法规则：`Ctrl`/`Alt`/`Shift`/`Win` 用 `+` 连接，最后一个是单个字母、单个数字、
`F1`~`F24`，或 `Left` / `Right` / `Space` / `PageUp` / `Home` / `Esc` 这类有名字的键。
至少要带一个修饰键（否则会把普通按键从别的程序手里抢走）。留空 = 不注册。

写错不会阻止保存，但会记进日志并且不生效；被别的程序占用时（典型是显卡驱动的
「旋转屏幕」抢了 `Ctrl+Alt+方向键`）也只是记一条日志，界面上换一个写法即可。
五个快捷键都在「设置」页改（播放页只留一个 NSFW 按钮，它和暂停/上一张/下一张在同一行，
这样播放页不用滚动就能看全两块屏）。

> 「显示主界面」是给**默认不显示窗口**这种用法准备的：程序启动后只留托盘图标，
> 而托盘图标可能被折进溢出区，这时按一下快捷键就能把窗口叫出来，不必去双击 exe。

## 环境要求

### 用交付版（`release\WindowsWallPaper\`）

| 要求 | 说明 |
| --- | --- |
| Windows 10 或更高 | 用到 `IDesktopWallpaper`（Windows 8+）与托盘图标。Windows 11 当然可以 |
| WebView2 运行时 | 界面是 WebView2 渲染的。Windows 11 自带；Windows 10 上如果没装，去微软官网装 Evergreen 版 |
| 桌面壁纸接口 | 逐屏设置壁纸用 `IDesktopWallpaper`。不支持 Windows 7 |

不需要 .NET、不需要 Rust、不需要 Bun。**整个文件夹拷走就能用。**

### 从源码构建

| 工具 | 用途 |
| --- | --- |
| [Bun](https://bun.sh/) | 前端依赖与构建（也可以用 npm/pnpm，但脚本里写的是 `bun run`） |
| Rust（stable） | 后端。`edition = 2021` |
| PowerShell 7（`pwsh`） | `scripts/` 下的脚本 |
| WebView2 | 同上 |

```powershell
bun install                 # 装前端依赖
bun run app:dev             # 开发模式：起 Vite + 编译 Rust + 打开窗口（热重载前端）
```

### 跑测试

```powershell
cd src-tauri
cargo test --workspace
```

**168 项测试，分两批**：

| 批次 | 数量 | 内容 |
| --- | --- | --- |
| `windows_wallpaper`（外壳） | 12 | 命令层的结果翻译、诊断导出 |
| `wwp_core`（引擎） | 156 | 配置、索引、扫描、筛选、选择器、壁纸匹配、图像处理、日志轮转 |

### 为什么 `wwp-core` 不允许依赖 `tauri`

这是整个工程结构里最重要的一个约束。`wwp-core` 是引擎——路径解析、配置、图库索引、筛选、
选择器、壁纸设置、图像预处理。它**不依赖 `tauri`**，因此：

- 那 156 项测试能在**无头环境**里跑，不需要图形界面、不需要真的改桌面壁纸；
- 想换掉界面框架（Tauri → 别的）时，引擎不用动；
- 测试跑得快（全部 156 项约 3 秒），因此可以频繁跑。

代价是有些东西必须**从引擎里提出来**才能测。一个具体例子：视频呈现需要建窗口、要有 D3D
设备，测试里跑不了。于是"把某块屏换成视频"这件事做成 `engine::VideoPresenter` trait
（默认实现返回明确的错误，而不是假装成功），测试塞一个记录用的假实现，
就能把"视频走视频路径、切回图片时先停视频"这条路由逻辑完整测出来。

**凡是新增功能，先问一句"它的判断能不能抽成一个不碰系统 API 的纯函数"。** 能抽就能测。

## 构建交付文件夹

```powershell
pwsh -File scripts/build-package.ps1
```

产出 `release\WindowsWallPaper\`——一个可以直接整体拷走的文件夹（不产出安装包、不产出压缩包）。

脚本做四件事：

1. `bun run tauri build --no-bundle`（内部会构建前端并**把前端产物嵌进 exe**）；
2. 把 exe 与图标复制进 `release\WindowsWallPaper\`；
3. **校验 exe 里确实含前端产物**——避免又产出一个"白窗口"版本；
4. 报告产物清单与大小。

### 两个开关

| 开关 | 作用 |
| --- | --- |
| `-CleanData` | 清掉运行时数据（`data/`、`logs/`、`webview2/`、`wwp-data-location.txt`），但**保留 `config/`** |
| `-SkipBuild` | 跳过编译，只用现有的 exe 重新组装交付文件夹 |

默认**不删**任何东西，以免把正在用的配置和索引删掉。要一份干净的交付产物时加 `-CleanData`——
它清掉的都是能重建的（图库索引、壁纸缓存、WebView2 数据），而 `config/` 里是你自己调的设置
（每屏筛选、间隔、目录选择），**删了就丢，重建不出来**，所以它被保留。

### 必须用 `tauri build`，不能用 `cargo build`

这一点实测确认过，而且**症状具有误导性**：

```
cargo build --release   →  exe 里搜不到前端 bundle 的文件名
                           运行起来窗口显示 WebView2 的"无法访问此页"
```

裸 `cargo build` 不会执行前端构建、也不会把 `dist/` 嵌进可执行文件。程序能启动、日志正常、
托盘也正常，**只有窗口内容是空的**——很容易被误判成"WebView2 没装"或者"前端代码有问题"。

打包脚本因此会在组装前**在 exe 的字节里搜前端 bundle 的文件名**，搜不到就直接报错退出。
这条校验挡住过一次真实的失误：中途用 `cargo build --release` 单独编译过（为了跑一个命令行
诊断入口），导致 exe 里嵌的是旧的 bundle，而 `dist/` 已经是新的。

## 配置文件

位置：`<数据根目录>\config\settings.toml`。

界面上能改的东西都会写回这里，所以**平时不需要手改**。手改也是支持的——程序每次启动读它，
改坏了最坏情况是那一项取默认值（大部分字段带 `#[serde(default)]`）。

```toml
libraries = [
    'D:\Pictures\壁纸',
]

[general]
interval_seconds = 100
fit_mode = 'fill'
minimize_to_tray = true
start_minimized = true
auto_start = true
pause_on_fullscreen = false
tray_click_action = 'open-window'
cleanup_expanded = true
layer_mode = 'toplevel'
volume_percent = 100
muted = false
video_enabled = false

[[playlists]]
id = 'list1'
name = '工作'
libraries = [
    'D:\Pictures\壁纸',
]
interval_seconds = 100
fit_mode = 'fill'

[monitors.'\\.\DISPLAY1']
current_playlist = 'list1'

[monitors.'\\.\DISPLAY1'.filter]
aspect_min = 1.3

[monitors.'\\.\DISPLAY2']
current_playlist = 'list1'

[monitors.'\\.\DISPLAY2'.filter]
aspect_max = 1.3

[exclude]
dirs = []
```

### `libraries` —— 图库清单（放图片的根目录）

顶层键，可以写多个。**增删的入口只有界面「图库」页的「新增图库 / 移除」**——
播放列表那一层只负责勾选，不能在这里凭空加一个。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `libraries` | 字符串数组 | 每个元素是一个放图片的根目录。顺序就是界面上列出来的顺序 |

> 一个图库**可以**不被任何播放列表引用：那时它不会被播到，界面上标成「未被使用」。
> 移除一个图库时，引用它的播放列表会一并解绑（磁盘上的文件和索引都不删——
> 再用同一个路径加回来时可以直接复用索引）。
>
> 这是**顶层键，必须写在文件最前面**（所有 `[表]` 之前）：TOML 规定裸键只能出现在
> 第一个表头之前，写到 `[general]` 后面会被算进 `general` 表里。

### `[general]` —— 启动行为，以及"新建列表时的兜底值"

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `start_minimized` | 布尔 | `true` | 启动时**不显示主界面**，只留托盘图标。改成 `false` 就会开机直接把窗口打开 |
| `auto_start` | 布尔 | `true` | 启动后自动开始轮播。**不看上次是否暂停过**：开着就一定会轮播 |
| `pause_on_fullscreen` | 布尔 | `false` | 某块屏上有程序全屏时**只暂停这块屏**的壁纸轮播，另一块屏照常；退出全屏后自动恢复（**从暂停处接着算**，不会重新计时）。"全屏"包含独占全屏、无边框全屏，以及**最大化的窗口**。它与界面上的「暂停」是两个独立原因，互不解除 |
| `nsfw_hotkey` | 字符串 | `Ctrl+Alt+S` | NSFW 模式的全局快捷键。留空 = 不注册。写错只记日志、不阻止保存。旧配置里这个字段叫 `safe_hotkey`，照样读得进来 |
| `pause_hotkey` | 字符串 | `Ctrl+Alt+P` | 全局"暂停/继续"（作用于所有屏） |
| `next_hotkey` | 字符串 | `Ctrl+Alt+Right` | 全局"下一张"（所有屏各换一张） |
| `previous_hotkey` | 字符串 | `Ctrl+Alt+Left` | 全局"上一张"（所有屏各退回一张） |
| `show_window_hotkey` | 字符串 | `Ctrl+Alt+W` | 全局"显示主界面"：把设置窗口显示出来（取消最小化并拿到焦点）。不改壁纸、不改播放状态 |
| `cleanup_expanded` | 布尔 | `true` | 设置页「清理程序目录」那张卡片是否展开。用户在界面上折叠一次就记下来，下次进设置页照旧收着 |
| `tray_click_action` | 字符串 | `'open-window'` | 单击托盘图标做什么：`'open-window'`（打开主界面）或 `'next-wallpaper'`（换一张壁纸；此时**双击**托盘图标打开主界面）。右键始终是菜单 |
| `minimize_to_tray` | 布尔 | `true` | 关窗口时隐藏到托盘（而不是退出）。关掉它则关闭窗口就等于退出（退出不还原壁纸） |
| `interval_seconds` | 整数 | `100` | 新建播放列表时用的间隔初值。**运行时的间隔来自每块屏选中的播放列表**，不是这里 |

| `fit_mode` | 字符串 | `'fill'` | 同上，新建列表时的填充初值。`'fill'` / `'fit'` / `'stretch'` / `'center'`（界面上显示成 `Fill` / `Fit` / `Stretch` / `Center`，中文含义在「填充」标签的悬浮提示里） |
| `layer_mode` | 字符串 | `'toplevel'` | 视频宿主窗口的形态。**当前固定不启用**（视频接线已删除），保留字段只为不破坏旧配置 |
| `volume_percent` / `muted` / `video_enabled` | — | `100` / `false` / `false` | 同上：视频相关的历史字段，当前不生效 |

> 为什么保留 `layer_mode` 这些已经用不到的字段？因为解析失败会让**整份设置退回默认值**
> （图库、每屏筛选、排除规则一起丢）。少一个字段而炸掉整份配置，代价远大于留三个死字段。

### `[[playlists]]` —— 播放列表（内容在这里定）

一个列表可以关联**多个**图库，但这些图库必须先在「图库」页的清单里。
每块屏通过 `current_playlist` 指向其中一个。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 稳定标识，由程序分配（`list1`、`list2`…）。界面改名字不会让"哪块屏在用哪个列表"失效，因此绑定关系引用的是 id |
| `name` | 字符串 | 显示名，随便改 |
| `libraries` | 字符串数组 | 这个列表用上面 `libraries` 清单里的哪几个。**一个图库可以被多个列表共用** |

| `interval_seconds` | 整数 | 这个列表的换图间隔（秒），范围 10 ~ 86400。**默认 100** |
| `fit_mode` | 字符串 | 这个列表的填充方式 |

顺序/间隔/填充为什么属于列表而不是显示器：一套精选图想慢慢看、一套随手拍的可以快翻，
所以它们是**内容相关**的属性；而长宽比筛选是**屏幕的物理属性**（竖屏就该只留竖图），
换列表不该改变它。

### `[monitors.'<显示器名>']` —— 每屏设置

键是显示器名，形如 `\\.\DISPLAY1`。这个名字由 Windows 给出，可以在「诊断」页看到当前有哪几块。
**键必须用单引号**：显示器名里的反斜杠序列在双引号里不是合法转义，会让整个
`monitors` 段落解析失败（那样每屏设置会全部失效）。

> **界面上可以给每块屏起个名字**：在「播放」页**双击显示器名**（`\\.\DISPLAY1`）就地改名，
> 只支持英文/数字（连字符与下划线也可以）。存的就是下面那个 `label`。
> 它**只影响显示**：配置键、日志、`data/output/` 里的产物名仍然用真实显示器名，
> 因此改名不会让任何绑定或缓存失效。

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `current_playlist` | 字符串 | `''` | 这块屏当前用哪个播放列表（填 `Playlist::id`）。**空串 = 这块屏不换纸** |
| `nsfw_wallpaper` | 字符串 | `''` | NSFW 模式时这块屏显示哪张图（完整文件路径）。空串 = 没设置。旧配置里这个字段叫 `safe_wallpaper`，照样读得进来 |
| `single_image` | 字符串 | `''` | 这块屏的**固定单图**。非空时它优先于 `current_playlist`：只显示这一张、不轮播。空串 = 按播放列表轮播 |
| `label` | 字符串 | `''` | 界面上的显示名（双击显示器名改的那个）。只保留英文/数字/空格/`-`/`_`；空串 = 显示真实显示器名 |

> **"某块屏不轮播"只有一个做法：不给它设播放列表。**
> 早先还有一个 `enabled` 开关，但它与"有没有选列表"是两套说法，用户很难分清是哪个在起作用，
> 因此已经删除。旧配置里的 `enabled` 会被忽略（不影响其它字段的解析）。
>
> `single_image` 是另一种"不轮播"：它明确指定要显示哪一张图。
> 它优先于播放列表，而播放列表里只剩**填充方式**对它有意义——单图不轮播，
> 顺序与间隔都用不上。

### `[monitors.'<显示器名>'.filter]` —— 每屏筛选

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `aspect_min` | 浮点？ | 未设 | 长宽比**下限（宽÷高）**。**包含**这个值 |
| `aspect_max` | 浮点？ | 未设 | 长宽比**上限**。**不包含**这个值 |
| `min_width` | 整数？ | 未设 | 最小宽度（像素）。**包含**这个值 |
| `min_height` | 整数？ | 未设 | 最小高度（像素）。**包含**这个值 |

#### 长宽比是半开区间 `[下限, 上限)`

**含下限、不含上限。** 两个边界的语义**故意不一样**，理由是相邻区间要能**无重叠地拼接**：

```
主屏  aspect_min = 1.3     →  取 [1.3, ∞)   即横图
副屏  aspect_max = 1.3     →  取 [0, 1.3)   即竖图
```

这样正好把所有图分完、不重不漏。**如果两端都包含**，比值恰好等于 1.3 的图会**同时**落进
两块屏——用户会看到同一张图在两块屏上各出现一次，而且很难联想到是边界值的问题。

界面上这个区间只需要填两个数字（格子刻意做小），**含下限、不含上限**的含义写在
「图像比例筛选」这个标签的悬浮提示里。**文字必须与代码一致**：用户填一个数字时不会去翻文档，
而写错一个边界值不会报错，只会让某张图默默出现在错误的屏幕上。

### `[exclude]` —— 全局排除规则

只有一类规则：**目录路径前缀**。它作用于完整路径（比较前统一转成小写、
分隔符统一成 `/`，因为 Windows 路径大小写不敏感）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `dirs` | 字符串数组 | 目录路径**前缀**匹配：命中则整棵子树跳过 |

**用前缀匹配是有意的**，因为界面上那个目录树的勾选就存在这里：

- 取消勾选一个父目录 → 只往 `dirs` 里写**一条**父目录路径，它全部子目录自动都不参与；
- 这意味着界面上"取消勾选父级则子级全不参与"不需要逐个写入。

> 原先还有 `globs`（通配符）与 `regexes`（正则）两类规则、以及一个专门的
> 「排除规则」界面页。按用户要求**已整体删除**：他只通过图库页的目录复选框
> 排除目录。旧配置里残留的 `globs` / `regexes` 段落会被安静忽略，不影响其余设置。
> 每屏的 `[monitors.'<名>'.exclude]` 也一并删掉了（它从来没有界面入口）。

## 数据目录

程序把运行时数据放在**数据根目录**旁边。默认就是程序所在目录（便携模式）。

### 数据根目录是怎么定的

按顺序判断，第一个可写的胜出：

| 优先级 | 位置 | 何时使用 |
| --- | --- | --- |
| 1 | 环境变量 `WWP_HOME` 指定的目录 | 自动化测试、想固定数据位置时 |
| 2 | 工程目录 | **开发态**：可执行文件在 `target/` 下时，数据改放工程根目录 |
| 3 | **程序所在目录** | 便携模式的正常情况 |
| 4 | `%LOCALAPPDATA%\WindowsWallPaper` | 程序目录不可写时（装在 `Program Files` 里就是这种） |

判定用的是"真的往里面写一个探测文件"，而不是看权限位。当前用的是哪一种，
在「诊断」页的「数据位置来源」一行能看到，`--diagnose` 也会打印。

目录里会留一个 `wwp-data-location.txt` 标记文件，写明数据根目录与它的来源，便于事后核对。

### 各子目录装什么

| 路径 | 内容 | 删掉会怎样 |
| --- | --- | --- |
| `config\` | `settings.toml`——你的全部设置 | **会丢设置**，重建不出来（每屏筛选、间隔、目录选择都要重设） |
| `data\index\` | 图库索引（每个图库一个子目录，里面有 `index.jsonl` 与 `index.meta.json`） | 安全。下次扫描重建，只是要重扫一遍 |
| `data\output\` | 换纸时按屏幕尺寸裁切/缩放好的 BMP；另有每屏的 NSFW 壁纸 `{屏}-nsfw.bmp` 与固定单图 `{屏}-single.bmp`（各有 `{屏}-nsfw.src` / `{屏}-single.src` 记录它是从哪张源图做的） | **安全**。轮播每块屏固定两个文件名轮换覆盖写，因此这个目录几乎恒定大小。删掉会按需重建 |
| `data\trash\` | **软件回收站**：播放页「删除当前壁纸」删掉的图都放在这里，**一个条目一个目录**（`<删除时间>-<原名>\`，里面有图片本体与记录原位置的 `origin.json`） | 安全。删掉就等于把这些图彻底丢掉（程序不再引用它们） |
| `data\trash-thumbs\` | 回收站相册页的缩略图缓存（每张一个 360 px 的 JPEG，几十 KB） | 安全，按需重建 |
| `data\wallpaper-thumbs\` | 「播放」页当前/下一张预览的缩略图缓存（同样是 360 px 的 JPEG，按图片内容命名；最多留 500 张，超了删最久没用过的） | 安全，按需重建 |
| `data\diagnostics-<时间戳>\` | `--export-diagnostics` 的产物 | 安全 |
| `data\nsfw-state.json` | 是否处于 NSFW 模式（一行 JSON） | 删了就等于“下次启动正常轮播” |
| `data\window-state.json` | 上次退出时的窗口大小（逻辑像素，一行 JSON）。它是**运行时状态**、不是设置，因此没写进 `settings.toml` | 删了就等于下次用默认大小（1400×950）启动 |
| `logs\` | `app.log`（超过 5 MB 轮转，最多留 5 个）、`crash\` | 安全 |
| `webview2\` | WebView2 的用户数据目录 | 安全，只是下次启动要重新初始化 |

`webview2\` 被**显式**指到数据根目录下。不这么做的话 WebView2 会默认写
`%LOCALAPPDATA%\<bundle-id>\EBWebView`，便携性就被破坏了——拷走文件夹之后
界面状态却跟着原来的机器走。

`data\output\` 里每块屏固定两个文件（`DISPLAY1-0.bmp` / `DISPLAY1-1.bmp`），
换纸时轮换覆盖写：这样磁盘占用恒定，也不会覆盖系统正在读的那一张。
代价是点「上一张」会重新解码一次（30 MP 的照片实测约 130 ms），换来的是
没有哈希命名、没有目录清理、没有几百 MB 的缓存堆积。

NSFW 壁纸与固定单图各用**一个**固定文件名（`DISPLAY1-nsfw.bmp` / `DISPLAY1-single.bmp`），
与轮播那两个槽位不共用名字：两套机制互相覆盖不了。单图按用户要求**只留一份**，
换了源图就覆盖它（用文件时间戳判断要不要重新解码）。

## 命令行入口

exe 支持一批命令行入口。**绝大多数是排查工具，日常用不到**——日常直接双击。

release 构建是 Windows 子系统程序，**没有控制台**，因此所有输出都会写进
`logs\app.log`；只有在终端里运行时才会同时打印到屏幕。

### 只读诊断（不改桌面）

| 入口 | 用途 |
| --- | --- |
| `--diagnose` | 打印版本、程序目录、数据根目录与来源、配置/索引/日志/WebView2 目录、标记文件路径 |
| `--probe-desktop` | 只读报告当前桌面的窗口拓扑（Progman / WorkerW / 任务栏 / 我们的窗口） |

### 锁屏壁纸：本程序不碰

微软没有给普通桌面程序留下设置锁屏图片的接口，而且这是**有意的设计**——做动态壁纸
最成熟的 Wallpaper Engine，官方文档写得很直白：Windows 登录屏幕按设计就是不可修改的，
"目前没有任何已知的安全做法"。

**本程序不会去改你的锁屏。** 2026-10-06 试过两条绕开的路，**都不通**，因此这个功能不做：

- **让锁屏「幻灯片」读一个我们维护的目录**：实测在「图片」模式设过之后，再切「幻灯片」
  并指定文件夹**不生效**；探针写进目录的测试图也从未在锁屏上出现过；
- **指向一个我们控制的文件、之后改它的内容**：系统会把图**拷贝**到自己的地盘
  （`C:\ProgramData\...\SystemData\S-1-5-18\ReadOnly\LockScreen_Z\`，文件名带目标分辨率
  与哈希，该目录的 ACL 只给 SYSTEM），改原文件不会影响锁屏。

剩下唯一可行的路是提权写 `HKLM\...\PersonalizationCSP`：需要管理员、官方文档只支持
Enterprise / Education（本机是 Pro），还会**锁死你自己在设置里改锁屏的能力**，因此也不做。
技术证据与结论留在 `AGENTS.md` §10.29。

## 已知的自动化验证局限

**这一节很重要。** 这个项目里有一批问题反复出现"脚本说没问题、但用户看到问题"，
根因都在这里。新增验证手段之前先读一遍。

### 1. WebView2 不接受合成点击

`click-window.ps1` 用 `SendMessage` 投递 `WM_*BUTTON` 消息，**WebView2 会忽略它**——
截图与日志都证实点击没有生效。

**因此界面交互（点按钮、输入文本、勾选）目前必须人工验证。**
可以脚本化验证的是：无界面的功能（`--diagnose`、`--scan`）、以及界面**读取**路径
（例如 `--probe-folder-tree` 走的就是「选择目录…」用的同一套判断）。

### 2. `emit()` 只在 stdout 是终端时打印

release 构建是 Windows 子系统程序，没有控制台。所有诊断入口的输出都会写进
`logs\app.log`，但**只有在终端里运行时才会同时打印到屏幕**。

从脚本或 GUI 里启动 exe 时，`stdout` 不是终端，因此**什么都看不到**。
这种情况下去读 `logs\app.log`。

### 3. GDI 截图看不到 DirectComposition 合成的内容

`BitBlt` 抓屏在 Windows 11 上可能看不到 DComp 合成的画面（硬件合成的内容不一定经过
GDI 可读的路径）。同理，DXGI 桌面复制取色的结果**不可重复**：同一个自检图案，
一次读到 `#FF00FF`、下一次读到 `#000000`。

因此"抓屏取色"这个手段的结论只能这样解读（原先有个 `sample-screen-colors.ps1` 做这件事，
已移除，但结论的读法仍然适用）：

- 抓到期望颜色 → 内容确实上屏了（**强证据**）
- 没抓到 → **不能**断定没上屏（弱证据）

### 4. 壁纸的"可见延迟"测不到

`IDesktopWallpaper::SetWallpaper` 返回得很快（API 调用本身 7~9 ms，加上准备位图后
48~71 ms），但 `GetWallpaper` 回读到新值要等约 **230 ms**——Windows 需要先转码图片、
再让桌面重绘。

这意味着两件事：

- **刚设完壁纸立刻回读会拿到旧值**，看起来像"设置失败了"。回读必须等一会儿。
- 日志里那个"换纸耗时"是**准备位图 + API 返回**的时间，**不是**用户已经看到新图的时间。
  画面真的换过去比那个数字晚一个数量级。

精确的**可见**延迟目前测不到，因为抓屏看不穿 DComp（见上一条）。

### 5. 只有用户本人能确认"屏幕上真的出现像素"

把所有自动手段加起来，仍然**无法**回答"这块屏上现在显示的是不是我以为的那张图"：

| 手段 | 为什么不行 |
| --- | --- |
| GDI `BitBlt` 抓屏 | 看不到 DComp 内容 |
| DXGI 桌面复制 | 结果不可重复 |
| DWM 属性查询 | `DWMWA_EXTENDED_FRAME_BOUNDS` 失败，且原因是窗口身份，不能当判据 |
| `GetWallpaper` 回读 | 只能证明"系统记下了这个路径"，不能证明"画出来了"；而且要等约 230 ms |
| 枚举窗口 | 能证明"没有东西盖住桌面"，不能证明"壁纸画对了" |

**所以凡是最终效果的问题，都需要人眼确认。** 本文档里那些"实测通过"的说法，
指的都是在这些局限之内能验证的部分。

## 换纸开销与后台占用

换一张壁纸必须**落盘**：`IDesktopWallpaper::SetWallpaper` 接受的是文件路径，
系统不会替我们把原图裁成"这块屏的确切尺寸 + 你要的填充方式"。因此每一步的开销
都值得量出来，而不是猜。下面这些是**实测值**（开发机：4480×6720 的约 30 MP 照片，
目标 3840×2160 与 1440×2560）。

| 环节 | 改前 | 改后 | 做法 |
| --- | --- | --- | --- |
| 解码 | 135 ms | ~105 ms | 解码后改用 `into_rgb8`，省掉一次整图（90 MB）拷贝 |
| 重采样 + 裁切 | 70~108 ms | ~55 ms | `Fill` 不再"先放大到覆盖画布再裁掉多余"，而是让重采样器只读源图上对应目标长宽比的那块区域 |
| 落盘 | 52 ms（23 MB BMP） | 52 ms | 保留 BMP：实测 JPEG 省了磁盘但多花一倍多时间（120~138 ms），质量也不够 |
| **每张合计** | **358 ms（横屏）/ 208 ms（竖屏）** | **225 ms / 185 ms** | |

另外两件事：

- **换纸线程被降到"低于正常"优先级。** 上面那两百多毫秒会占满一个核，
  而壁纸早几十毫秒换完对用户没有区别；降级之后 Windows 会把 CPU 优先让给
  前台程序（游戏、播放器、会议），因此"换纸时前台卡一下"不会发生。
- **`data\output\` 不再累积。** 每块屏固定两个文件名轮换覆盖写，磁盘占用恒定；
  原先按内容哈希命名并保留最近 24 个文件（4K 下一张 24 MB，峰值约 600 MB），
  每换 8 次还要遍历一次目录做回收。这些机制连同"命中缓存不重新解码"的优化
  一起删掉了——那份收益只体现在「上一张」，而代价是持久的磁盘与目录开销。

### 常驻时的占用

不换纸的时候，程序做的事情只有三件：一条每秒一次的状态轮询（界面侧）、
每屏一个计时线程（每 250 ms 醒一次判断是否到点）、以及一条系统广播监听。
图片壁纸由系统渲染，程序侧**不持有任何窗口、不建 D3D 设备**。
（视频壁纸需要的那层宿主窗口已经删除，见文首说明。）

## 排查入口

### 第一步：看日志

```
<数据根目录>\logs\app.log
```

在「诊断」页可以直接看到它的完整路径（`--diagnose` 也一样）。

日志超过 5 MB 会轮转，最多保留 5 个文件（`app.log`、`app.1.log`……最旧的被丢弃）。

**按级别过滤**：

```powershell
Select-String -Path logs\app.log -Pattern '\[ERROR|\[WARN' | ForEach-Object { $_.Line }
```

`[ERROR]` 是真正的失败。`[WARN]` 是"能继续但有东西不对"——例如某个目录读不了、
某块屏暂时不在枚举结果里。

> **诊断信息不会冒充错误。** 窗口几何这类信息记在 DEBUG 级别（日志格式里 DEBUG 行
> 不带级别标记）。因此按 `[ERROR]` 过滤得到的就是真正的错误，可以直接用它判断
> "这次运行有没有问题"。这一条是被一次教训逼出来的：早期几何诊断走的是"记成错误"
> 那条路，于是 `[ERROR]` 计数永远是非零的，那个指标就没人看了。

日志级别是 **Debug**（不是 Info）。这是刻意的：排查"界面显示的值不对"这类问题时，
关键信息往往在 Debug 里，而默认只记 Info 会让现场消失。

### 第二步：确认数据位置与版本

```powershell
.\WindowsWallPaper.exe --diagnose
```

输出（同时写进日志）包含版本、程序目录、数据根目录**与它的来源**、以及各子目录的实际路径。
"数据位置来源"是 `program-dir` 才说明便携模式生效；`fallback-localappdata` 说明程序目录
不可写，数据跑到系统目录去了。

### 第三步：导出诊断包

```powershell
.\WindowsWallPaper.exe --export-diagnostics
```

产出在 `data\diagnostics-<时间戳>\`，包含：

| 文件 | 内容 |
| --- | --- |
| `environment.txt` | 版本、系统、显示器/DPI、显卡、桌面层拓扑、当前壁纸 |
| `settings.toml` | 当前设置的副本 |
| `index-stats.txt` | 每个图库的索引统计（**不含**完整索引文件，那可能几 MB） |
| `playback.txt` | 轮播状态与每屏当前显示的图 |
| `app-log-tail.txt` | 最近 800 行日志（整份日志可能几 MB，有用的通常是尾部） |

这条入口**不打开窗口也能跑**。这很重要——用户可能遇到"界面起不来"，
而那正是最需要诊断信息的时候。

### 常见现象对照

| 现象 | 先查什么 |
| --- | --- |
| 双击后"什么都没发生" | 默认启动就不显示主界面。**看通知区域有没有托盘图标**（`scripts\probe-tray.ps1`），点它即可打开界面 |
| 屏幕一片灰，或退出时闪一下 | `scripts\probe-layer-windows.ps1`——**有没有窗口盖住壁纸**（视频管线已删除，正常应当没有任何宿主窗口） |
| 某块屏一直不换纸 | 先看那块屏有没有选播放列表；再查日志里那屏的"候选 N 张"，N 为 0 说明筛选条件把图都挡掉了 |
| 界面能开但内容空白 | 是不是用 `cargo build` 编的（见「必须用 tauri build」） |
| 换了设置但没生效 | 一般保存时就生效了；还是不对就点播放页的「重新加载」（= 按当前设置重建，当前壁纸不动，到下一个间隔才换） |
| 点「重新加载」时界面卡住 | 不该发生。它只调用现有的启停命令，不做同步扫描；卡住请连同 `logs\app.log` 反馈 |
| 扫描进度不动 | 看浮窗上的**已用时**。秒数在走而进度数字不动 = 卡住了但线程还活着，可以点取消 |
| 日志里刷满同一行 | 先看那条是什么。正常运行时日志应该是稀疏的 |

## 界面结构

左侧六个页面：

| 页面 | 内容 |
| --- | --- |
| **播放** | 顶部一行：轮播启停、**NSFW**（绿 = 未开启、红 = NSFW 模式中）、重新加载；每屏一个区块：**双击显示器名可改名**、**当前显示 / 下一张两格预览**（缩略图 + 路径，下一张还带倒计时，暂停时倒计时照显示、「已暂停」排在旁边；点缩略图 = 打开这张图 / 立刻切过去，**点那行路径 = 打开所在文件夹并选中它**，**右键那行路径 = 复制文件名（不含扩展名）**）、播放列表选择、固定单图、NSFW 壁纸、已切换次数、候选数、**图像比例筛选**（右对齐那一行），以及右上角的**删除当前壁纸**（把它移进软件回收站并换下一张）与只停这一块屏的暂停 |
| **图库** | 顶部**「全部重新扫描」**（一次把所有图库都增量重扫，逐个图库列出新增/更新/删除）；图库目录（**「新增图库 / 移除」在这里**、**底色表示建没建索引**、打开目录/扫描/全量重扫/目录树勾选，目录树在**所点那一行的下方**展开）、扫描进度与结果明细 |
| **列表** | 每个列表一行：新建/改名/**拖手柄排序**/**勾选图库**（顺序与图库页一致）/间隔与填充/删除 |
| **回收站** | **相册形式**列出被删掉的图：缩略图 + 文件名 + 删除时间 + 原位置；每张下面**恢复**（绿底）/ **删除**（红底）；顶部有**全部删除**、打开文件夹、刷新；并显示**回收站的完整路径** |
| **设置** | 五个全局快捷键、启动与窗口开关、单击托盘图标的行为，以及**「清理程序目录」**（默认展开，列出可清理项、默认全选、确认后删除；**回收站、设置与图库索引不在其中**）。**回收站相关只出现在回收站页** |
| **诊断** | 数据位置、全部目录路径（含**回收站目录**）、索引概况、导出诊断包 |

左侧下方常驻版本号。保存设置时右上角浮出提示（2.5 秒后消失），**不顶动页面布局**。
扫描期间右上角另有一条常驻浮窗显示进度与已用时（一次扫全部图库时还会显示**第几个/共几个**），
**切到别的页面也看得到**。扫描结果本身留在页面上，直到下一次扫描开始或你点「关闭」——
它要回答的是"变了什么"，闪几秒就没了等于没给。

**界面上不堆说明文字。** 需要解释的地方一律写成跟随鼠标的悬浮提示（`Tooltip.tsx`），
而且只写具体含义、不写长篇原理；实现理由留在代码注释与本文件里。

### 想改界面上的悬浮提示？改 `frontend\tooltip-texts.ts`

界面上所有"悬停才出现"的文字（跟随鼠标的提示，以及按钮上的 `title`）都集中在
[`frontend/tooltip-texts.ts`](frontend/tooltip-texts.ts) 里，每一段上面都有一行注释
说明"它显示在哪里"。改完**必须重新构建**才生效（`pwsh -File scripts\build-package.ps1`）——
这些文字是在构建时被打包进 exe 的，程序运行时不读任何配置文件，也就是说
**编译出来的程序里这份文案是固定的**。

极少数提示里嵌了运行时的值（显示器真实名字、图库路径、数量），它们写成了函数，
文字照样能改，但函数体里的 `${...}` 插值不要动。
